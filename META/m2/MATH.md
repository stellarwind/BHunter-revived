This pass reads their complete assembly in `math/original/`; no function boundary or historical header/compiler context is changed. The behavioral question is whether the C variant agrees with the ten original pure functions over broad finite magnitudes, cancellation, signed zero, subnormals, exceptional values and allowed aliases, under PC53/nearest/masked exceptions. PC24 and PC64 are diagnostic profiles, not presumed supported game states. Record classification/return/bit/ULP/exception differences separately; NaN comparisons must not silently pass through a tolerance check.

It still calls only the same ten pure functions and relocates only the same four normalization constant operands in private memory. No game entry point, subsystem or new original function is admitted to that mapper. The default integration target remains source-only, and checked-in numerical fixtures can support it without the original EXE.

No compiler-flag or byte-match sweep is planned. If a mismatch needs explanation, use its saved inputs, the assembly operation grouping and the world-translation positive control. Stop a focused code-generation investigation after one bounded block or repeated identical output; retain explicit limits instead of inventing source or assembly fallbacks. The separate matched C++ artifact and historical fixture/result files remain unchanged.

The initial observed original state is PC53 (verified `__setdefaultprecision` at 0047e930), but later driver/thread transitions still need runtime evidence. A source numerical profile may be explicitly constrained and verified at an integration boundary; it is not proof of the original game's full runtime state or blanket permission for game admission. Matrix multiply/rigid inverse outputs must remain distinct from input storage unless further evidence establishes a supported alias contract.

## Supported numerical and alias contract

The supported build is the pinned VC5 C translation unit with `/ML /O2 /G5 /Oi /Gy`, real SP3 math/CRT headers and stock linker. Required x87 controls are PC53, nearest rounding and all six exceptions masked, including denormal. `src/bh_fp.c` provides explicit enter/check/leave helpers using `_control87`; `_controlfp` would ignore the denormal mask. The integration driver establishes the profile, checks it after the active scenarios and restores the caller's controls. Kernels have this precondition and do not alter controls themselves. Callers on future game/backend threads must establish and verify the same boundary contract.

Scopes nest on the same thread and restore precision, rounding and exception masks. This is a control scope: CRT control operations may clear sticky exception state, and it does not promise full x87 status/register preservation. Tests clear fixture exceptions before leaving scopes. Do not use an active scope concurrently or leave it on another thread. Other precision/rounding profiles and unmasked exceptions are explicitly rejected by the checker, rather than silently treated as equivalent.

`BHVec3` is three floats (12 bytes); `BHMat34` is three rows of four floats (48 bytes), cdecl. Matrix multiply and rigid-inverse outputs must be distinct from input storage; multiplication may use the same matrix for both inputs with a distinct output. Cross product permits output equal to either complete input, equal input pointers, or all three equal. Point/direction/inverse-point and normalize-to permit the output equal to the complete vector input. Sequential stores intentionally affect later reads when aliased. Partial overlap and vector overlap with the matrix are excluded. World/local translation mutate the matrix. Inverse semantics assume an orthonormal basis; no general inverse is substituted.

Finite values, signed zeros and infinities are checked by exact output bits under this build/profile. Normalize returns zero and preserves its destination for zero or unordered length, including NaN; infinite length follows the observed reciprocal/invalid-result behavior. NaN output class and return behavior are covered, but NaN payload/sign are outside the accepted equivalence contract: rigid inverse has 54 payload differences per tested precision. Applications must not use those payloads as data. Observed FP exception flags match the oracle fixtures; this is measured coverage, not a universal sticky-status guarantee.

Broad cancellation cases exposed PC53 differences in the previous C source that the moderate historical fixtures missed. Matrix multiplication, point/direction transforms and local translation now preserve the addition grouping from the complete original instruction flows. `math/expression-audit.txt` records a read-only symbolic x87 tree audit for multiplication/local translation; full listings are in `math/original/`. No compiler flags, inline assembly, ABI or historical C++ matching context changed. Cross/normalization/inverse-point/world translation/rigid inverse source expressions did not need changes.

The baseline broad adversarial run recorded 391 failing PC53 cases (`oracle-baseline-adversarial.json`, earlier alias set). After correcting grouping, finite bits and returns match at PC53 and diagnostic PC64. World translation was the positive control. The stopping condition was agreement under the supported profile, with residual PC24 and NaN payload differences recorded; no flag sweep or byte-match investigation was pursued. PC24 inverse-point still has 3,596 finite-word differences, maximum 512 ULP, and is unsupported. No discrepancy is hidden by a numerical tolerance.

The old source is retained as `math/baseline-bh_math.c.txt`. Historical ledger records and differential results belong to that variant. Ten new `*-functional-c-pc53` records name the current source hash and linked evidence. The four C++ `bm` records remain separate object-only variants; none of their byte evidence is transferred to C. The three FP helpers are support adapters with no recovered-original-function count.

Analytical tests add varied-scale 3-4-5 normalization, orthonormal inverse composition, zero/NaN behavior, sequential alias semantics and FP profile rejection/enter/nested restore checks. Numerical checkpoint: 28,302 checks, zero failures.
