# Input polling source restoration

Complete004744f0 is restored as `bh_input_collect` in its real translation unit
`src/bh_input_collection.c`. The reviewed4421-byte/1107-instruction ordinary
engine owner calls WinMM and user32 and the existing binding evaluator. It is
not verified CRT/library code, compiler scaffolding, an import or a shared tail;
engine attribution remains unknown. `owner.json`, `PRE_REVIEW.md` and the raw
instruction export establish its original boundary and global relationships.

The explicit context owns the two availability/calibration flags, capabilities,
deadzone mask, eight observed minimum/maximum pairs and two signed mouse deltas.
It borrows the actual input-list owner and the snapshot already shared by the
message helper/evaluator. Its initialization adapter uses verified startup
defaults from00473d60 without claiming that larger initializer or its key-name,
capture and shutdown lifetimes are restored.

The full poller retains two-device X/Y/Z/R normalization, prior-poll calibration
selection, the strict observed-range threshold, four button bytes per device,
cursor read/recenter order,16-bit wrapping accumulated positions and separate
low words of32-bit raw deltas, double mouse-filter constants, full/edge list
evaluation and255-byte current-to-previous copying. The original pointer-range
debug fault is replaced by an explicit source topology check. Native API
failure is diagnosed instead of consuming uninitialized stack storage. See
`SOURCE_REVIEW.md` for these guarded-domain limits.

The default API bindings are real `joyGetPosEx`, `GetCursorPos`, `SetCursorPos`
definitions linked with winmm/user32. Tests override them only inside isolated
source fixtures to verify requests, order, status, sample arithmetic and
recenter coordinates. **No native recenter call occurs during validation.**
Read-only actual joystick/cursor queries are separately executed; no joystick
capture, external key injection, menus, flight or other game execution occurs.
The synthetic fixtures compose real owning input lists, message handling,
binding evaluation and packet consumers. Independent PC53 golden cases pin
axis saturation and retained/stored mouse-filter comparisons. Native device
loss behavior, actual capture/focus lifetime, human input fidelity and PC24
remain open. Parent integration/clean results are in `../frontier-90min/`.

## Device initialization and shutdown

The later implementation in `src/bh_input_devices.c` additionally restores the
complete00473d60 initializer and00473fe0 shutdown. It seeds the exact255-slot
original key-name data, preserves localized letter/fallback formatting, captures
device0 then1 at100ms, queries capabilities only after successful capture,
resets the established input/mouse/calibration defaults, and releases enabled
devices in order. `DEVICE_PRE_REVIEW.md` and `DEVICE_SOURCE_REVIEW.md` verify the
two raw bodies, varargs missed by decompilation and actual native structure
layout. Source allocation/lifetime adapters own only generated strings and
reject resetting a nonempty live input-list owner. Tests simulate capture/caps,
allocation failure and recenter calls in isolated API fixtures, with native
read-only key translation. No actual capture or recenter is executed. The
source initializer is recovered; its use by the complete application startup,
focus/loss handling and worker/window lifetime remain unimplemented.
