# Render callback frontier, independent raw PE review

Reviewed immutable `GAME_DATA/BHUNTER.EXE` assembly for `00479090..00479115`, its owned tail `00450930..00450978`, `0045ca10..0045cbbc` (429 bytes) and `0045cbc0..0045cded` (558 bytes). Combined two-range callback bytes, hashes and rel32 jump are recorded in `META/m4/hud-continuation/original/00479090.ranges.json`. `00479090` is the installed render callback, not a CRT routine. The tail is shared code reached by its jump and is part of this behavior, not an independent recovered function. `0045ca10` and `0045cbc0` are renderer-owned clear/present helpers. Their repeated direct callee `0047de20` is the CRT x87 float-to-int helper (`FNSTCW`, temporary truncation control word, `FISTP`, restore), so exclude it from gameplay assignments.

`00479090` compares global `004df250` to 1. Equal selects `0045cbc0(255,255,255)`; other values call `0045ca10()`. It drains the `004f54ec` read byte toward `004f54f0` write byte, indexing a 256-slot queue at `004f00d8` with 84-byte records. It invokes each record's first-word callback with the record pointer, rereads both queue bytes after that callback, increments/stores the read byte, and loops to the live write byte. It then takes its third argument as an initial draw-command pointer, invokes that record's first-word callback with the pointer, and repeats with each returned pointer until zero. Worker `00471ecf..00471ed4` supplies the frame buffer as that third argument. The tail tests `004e32f4`: nonzero returns; zero increments `004ede80`, traverses the `004edc70` linked batch list by `+10`, calls `004508a0` for each batch, and invokes graphics interface vtable slots `+2c` then `+28`.

`0045ca10` branches on `004e32f4`, then the active lock/surface flag `004e9c50`. Its software-memory path clears a rectangular region by zeroing two bytes per pixel for a computed positive row count, using pitch `004e38cc` and base `004e8ce0`. Its alternate path calls a surface vtable slot `+14` with a `0x3000000` color-fill flag and a 100-byte effects structure. With `004e32f4==0`, it increments the frame counter, flushes linked batches via `004508a0`, invokes the graphics interface slots `+2c/+28`, then performs the surface color-fill call. It does not independently establish the provenance of each COM implementation.

`0045cbc0` takes three color components and likewise branches on `004e32f4`. In the nonzero branch it first flushes pending batches and invokes slots `+2c/+28`; both branches then convert viewport floats with the CRT helper, derive color according to `004e38c4` format selection, and choose active-lock or surface methods. Its active-lock branch calls surface slots `+80`, `+14`, and `+64` (Unlock/Blt/Lock), retrying Lock at most 500 times and calling imported KERNEL32 `Sleep(1)` through IAT `00489050` on each failure. Lock success is tested against exact zero HRESULT (`TEST ESI; JE`), including positive nonzero values in the retry path. Both final paths call `0045ca10`. This broadens the dependency closure beyond a simple solid-color clear.

The batch flush callee `004508a0` is already admitted in source as `bh_texture_draw_flush`; it is not an open dependency. Admission limit: an offscreen/native-only check cannot establish the original software-memory and graphics COM branches above. The source contract must explicitly name its supported backend domain and linked source owners; no original code may be mapped or executed in a shipping target.

The landed `bh_frame_render.c` binds real DirectDraw surfaces and Direct3D2 device methods, and its native fixture exercises both a real unlocked native fill and a locked software-memory fill/Unlock/Blt/Lock round-trip. Indexed white correctly maps to palette value 251. The landed `bh_render_execute.c` follows the text ring then draw chain and includes a source guard for invalid selectors/topology. Review identified three narrow issues: signed `++textures->frame` in the tail can be undefined at the original 32-bit wrap point; storing `480.0f-top` into a binary32 temporary before integer conversion can differ from original x87 subtract-then-`__ftol` near integer boundaries; Lock retry must accept only exact zero HRESULT, not all nonnegative HRESULTs. Owners fixed all three. Color packing now has an explicit source domain of 0..255 components to avoid out-of-range signed arithmetic.
