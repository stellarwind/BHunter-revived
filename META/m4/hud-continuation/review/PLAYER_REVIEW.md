# Player scene and weapon factory review (2026-10-25)

Read-only review of immutable `GAME_DATA/BHUNTER.EXE` and PE-verified instruction exports in `META/m4/hud-attachment/next-player-review/`. Scope: complete scene `0041c860..0041d7bd` and factory `00433ea0..00433f6a`. This note is a contract review, not source admission or gameplay execution.

## Actionable assembly findings

1. **Fade color differs from the decompiler's apparent data flow.** At `0041c9ee..0041ca00`, x87 loads player `+24c`, computes `(1.0 - value) * -127.0`, and calls `__ftol`. At `0041ca0f..0041ca26` the color word is `(0xff00 - converted) << 8`, while the fade amount is the separately squared and clamped `+254` value. Raw PE constants: `00489220=1.0`, `00489930=-127.0`, `004892e8=0.9`, `00489300=0.05`, `00489318=0.1`. A source implementation must retain conversion/shift order and unsigned 32-bit color bits. The threshold is an x87 comparison of stored float `+254` against **double** 0.1: stored `0.1f` is above it. The `+254<=0.1` path calls fade `(0,0)` at `0041ca4e..0041ca52` and skips flash decay; the positive path updates `+254` after optional fade using `(0.65 - player[+23c]*-0.35)*old_flash` (`0041ca2e..0041ca46`). The alternative `frame>=150 && mode_count<=1` path derives fade amount from `frame-150`, caps at 1, and uses color zero; it does not mutate `+254`.
2. **Live callback reads.** Main gate tests byte `+2bb==1` and nonzero global `004dfb08`, then tail is reached even when main gate fails (`0041c872/0041c87f -> 0041d440`). Actor marker callback traversal loads successor `+118` *after* each `0041b650` call (`0041d1af..0041d1bf`). Primary weapon selector `+2b6` is loaded after markers and resolves player table `+258+4*index`; secondary selector `+2b7` is loaded only after the primary callback (`0041d1c1..0041d1ec`). Embedded camera mode `+e8` is reloaded after both callbacks for flat/world status. Mode count is reloaded after status for scoreboard, and display dimensions are read later for scene/confirmation. Do not snapshot those values before synchronous callbacks.
3. **RNG order and drops.** Positive transient `+240` queues exactly 32 iterations, each with three CRT `rand` calls before normalize and one after, preceding oriented submission (`0041d351..0041d43a`). The `<75` tail calls CRT `rand` immediately before each of four segment submissions (`0041d52f`, `0041d5d2`, `0041d675`, `0041d718`). These calls happen even when the associated queue consumer rejects publication. Branch combinations therefore consume 0/128 main and 0/4 tail random calls, in addition to selected weapon callbacks' consumption on the same CRT stream. A callback mutation can affect later tail branch conditions.
4. **Tail and raw queue reservations.** The `+21c` resource draw precedes the frame `<75` test, even on failed main gate. The `<75` section optionally reserves two records if `+2b4 & 0x10`; failure of the first reservation does not suppress the second, and failure of the second jumps to cockpit/segments. The second record writes nine words only after a successful reserve. Its width uses signed integer divide by two, which truncates toward zero for odd negative widths (`CDQ; SUB; SAR` at `0041d4b7..0041d50f`) before conversion to float. Cockpit resource `00496338` is submitted unconditionally on this branch; four segment calls follow. The square-root radicand is `z*z + x*x - y*y*const_00489990`; PE constant at `00489990` is float `-4.0`, so this is effectively `z*z+x*x+4*y*y`, but preserve the original operation order and single-precision stores for fidelity.
5. **Factory closure.** `00433ea0` is 203 bytes, returns null on pool acquire `00476f20` failure, and otherwise initializes one acquired object, installs six method pointers from `0048fa60+24*index` into `+12c,+130,+124,+128,+11c,+120` (in that write order), sets ammo limit `+110` from `0048fa38+4*index`, then registers query `00433e50` with `00476e90` before returning object identity. It zeroes `+e8,+f4,+f0,+f8,+fc,+ec,+104,+108,+10c,+114`, sets `+100=-1`, and does not establish a player weapon table or selected indices. The first stack argument is unused by this body. Original has no index-range check; a source guard is an explicit safety extension, not evidence of original behavior. Query `00433e50` is already admitted in `src/bh_weapon_removal.c`, but the factory, player constructor `00421d20`, selected method writers and object cleanup still require their own integration/lifetime evidence.

# Camera numerical domain

The source currently rejects nonfinite camera eye, angles, or velocity before the active scene while original `0041c860` has no such preflight. The implementation owner retained this as an explicit source-domain guard because downstream source 3D owners reject nonfinite state and documented the original NaN camera behavior as unverified in `src/bh_player_scene.h`. This limits all-body NaN fidelity claims but does not affect finite gameplay state.
