# Closed entity callback and numeric helpers

Six ordinary complete owners, engine provenance unresolved, are restored in
`src/bh_callback_helpers.c`. Read-only disassembly and caller/data references
classify the four event callbacks as installed entity behavior and the other
two as interpolation and network vector decoding. No CRT/import/EH helper or
shared tail is counted. The original inventory and exact immutable PE bytes
independently establish all six contiguous instruction boundaries; exports and
the exact double1/128 constant are checked by `export.py` before admission.

00402e20 handles event17 matching entity+1b4 and clears that reference;
00407180 matches+f4 and clears both+f4/+fc;00442330 matches+104 and clears it.
Other events/targets retain the whole entity.00407b00 answers event3 with the
actual entity+0c position and event20 by clearing+108. These callbacks take
borrowed real BHEntity/packet objects and preserve x86 offset/layout contracts;
NULL rejection is a source safety guard. Live constructor registration remains
outside this family; fixtures install the complete callbacks with actual source
pool registration and exercise actual query traversal and release owners.

00436670 is factor-first three-component interpolation. Double intermediates
under the pinned PC53 environment retain the original unrounded differences,
including the z non-popping FST. Exact endpoint/output aliases work; partial
overlap and arbitrary overlapping packets/entities are not supported contracts.
Fixtures cover endpoints, extrapolation, aliasing and a non-dyadic cancellation
discriminator producing0x3e800001 rather than prematurely rounded0x3e800000.

00423a10 consumes three signed bytes through the existing BHPacketReader
context, multiplying by retained scale/128 and storing binary32 components.
The original global cursor becomes explicit reader state. A short source buffer
rejects before output/cursor mutation (error becomes TRUNCATED). Fixtures build
and receive real source packet envelopes and check all256 byte values at five
scales, exact cursor state and short-buffer atomicity. They execute neither a
network session nor original code. Fully nonfinite input, x87 PC24/64, game-wide
runtime precision transitions and a playable game remain unvalidated.

All six require parent current full integration and clean build; independent
review of all six instruction exports found no contract mismatch. No byte-match
claim is made for these maintainable C implementations.
